Building the Procurement Policy Advisor in Oracle Fusion

An employee needs a new laptop. They open a requisition, and a question stops them cold. Does this need a quote? Is there a preferred supplier? What is the spending limit before a second approval kicks in? The policy that answers all of this lives in a PDF on a shared drive that nobody reads. So the employee guesses, and either the requisition bounces back or a non-compliant purchase slips through. This exact moment, repeated thousands of times a year, is what the Procurement Policy Advisor was built to fix.

It is one of the AI agents Oracle now ships inside Fusion, and it is a good first agent to learn because the value is obvious and the setup is contained. This entry covers what it does, why it matters, and how to actually stand one up.

What the Procurement Policy Advisor is

The Procurement Policy Advisor is a conversational agent embedded in the Redwood Self Service Procurement application. While an employee is creating a requisition, they can ask it plain questions about products, services, and policy, and it answers using your company's own documents. It is not a generic chatbot bolted onto the side. It reads the policy files you give it and responds in the moment, right where the work is happening.

Two business outcomes drive it. First, it streamlines access to policy and process documents at the point of creating a requisition, so nobody has to leave the screen to hunt for a rule. Second, it improves compliance by giving policy guidance as users submit requisitions, catching the guesswork before it becomes a problem.

The mechanism underneath is simple to describe. The agent has a document tool, which holds your attached and published procurement policy and guideline documents. When someone asks a question, the agent draws its answer from those documents. Good documents in, good guidance out.

Why this matters more than it looks

Procurement runs on rules that most requesters never learn, because learning them is not their job. The result is a slow, error prone middle layer where buyers field the same policy questions over and over and non-compliant requisitions get caught late, if at all. The advisor collapses that layer. It puts the rulebook inside the requisition, phrased as a conversation, available the instant a question comes up. That is a genuine shift in how compliance happens: from enforcement after the fact to guidance in the moment.

There is also a strategic reason to learn this now. Oracle has moved agent creation into a single place called AI Agent Studio, and it explicitly recommends that anyone who built agents before update 25C rebuild them there. Getting fluent in this setup is quickly becoming a core Fusion skill rather than a novelty.

Setup, start to finish

The build has a clear shape: turn on the platform, give yourself access, create the tool that holds the policy documents, wire it into an agent, and surface it to users. Here is the path, based on Oracle's own configuration guidance.

Step 1: Set the profile options. In Setup and Maintenance, open Manage Administrator Profile Values and set the enabling profiles to Y. The ones this flow depends on are ORA_HCM_VBCS_PWA_ENABLED, ORA_PER_GUIDED_JOURNEYS_SETUP_REDWOOD_ENABLED, and ORA_PER_AGENT_TASK_TYPE_GUIDED_JOURNEYS_ENABLED. Nothing works until these are on.

Step 2: Create the security role. In the Security Console, create a role, for example AI_AGENT_ADMIN_ROLE, and assign the privileges that let a user manage and use agents, including HRC_MANAGE_AI_AGENT_PRIV and HRC_ACCESS_AI_AGENT_CHAT_PRIV. Assign that role to yourself so you can do the rest of the setup.

Step 3: Build the policy tool. Navigate to My Client Groups, click Show More, and open the Configure Agents page for your area. On the Tools tab, add a new tool, give it a clear name such as Procurement Policies Tool, and attach the documents that make up your policy. This is the most important content step in the whole build, because the agent can only be as good as the documents behind it. Curate them. A clean set of current, well written policy files beats a pile of outdated ones.

Step 4: Create the agent from the template. Open AI Agent Studio from the Navigator under Tools. Find the Procurement Policy Advisor template and choose how to create it. Copy Template is the fast path: it builds the agent team and its artifacts automatically and drops you on the canvas to adjust. Use Template is the guided path: it walks you through configuring each piece one at a time. For a first build, Copy Template gets you working quickly, then you refine.

Step 5: Attach your tool and set security. On the agent team canvas, add the policy tool you created so the agent knows where to read from. Then, on the Security tab, set which roles can access the agent. This controls who actually gets the advisor inside their requisition flow.

Step 6: Surface it with a guided journey. The advisor reaches users through a guided journey on the Redwood Self Service Procurement page, enabled through Visual Builder Studio. This is what places the agent into the requisition experience rather than leaving it as a standalone tool. Configure the journey so the advisor appears where requesters will naturally reach for help.

Step 7: Test as a requester. Open the Redwood requisition flow and ask the advisor real questions your buyers hear every week. Does this category need a quote. What is the limit for this expense type. Who is the preferred supplier for laptops. Confirm the answers match your documents, then tighten the document set wherever an answer was vague or wrong.

A migration note worth knowing

If your organization built a policy agent before update 25C using the older RAG configuration, do not start over from nothing. Oracle provides a migration path. Go to My Client Groups, then Show More, then Configure RAG Agents, open the Tools tab, and use the Migrate action on your existing document tool. Give it a unique name and code and select the family and product, then locate that migrated tool in AI Agent Studio and attach it to a new agent built from the template. You keep the document work you already did and simply move it onto the current platform.

Ideas to make it genuinely useful

The default use is answering policy questions during requisition creation, and that alone earns its keep. A few ways to push it further:

Encode the tribal knowledge, not just the policy. The official policy document is the obvious input. The higher value input is the unwritten knowledge that lives in your buyers' heads: which supplier to use for which category, which purchases always need extra documentation, the thresholds people forget. Capture that as a clean guidance document and the advisor becomes a standing answer to questions that used to require a human.

Keep the documents alive. An agent pointed at a stale policy gives confidently wrong answers, which is worse than no agent. Treat the document set as something you review on a schedule, especially after quarterly updates or policy changes. The setup is one time; the document maintenance is the real ongoing job, and it is what separates an advisor people trust from one they learn to ignore.

Watch what people ask. The questions users bring to the advisor are a live map of where your policies are unclear. Recurring questions on the same topic mean the underlying policy or the document explaining it needs work. The agent becomes a feedback loop on your own procurement rules.

The honest limits

This is early technology and it deserves a clear eyed view. The advisor answers from the documents you give it, so its quality is entirely a function of that content. It guides, it does not enforce, so it complements approval rules rather than replacing them. And the setup touches profile options, security roles, and Visual Builder Studio, so it is a genuine configuration effort, not a switch. None of that diminishes the value. It just means the work is in the preparation, which is exactly where a good consultant earns their place.

The Procurement Policy Advisor is a small, sharp example of where Fusion is heading: expertise embedded directly into the moment of work, phrased as a conversation. Learning to build one well is a skill worth having now.
